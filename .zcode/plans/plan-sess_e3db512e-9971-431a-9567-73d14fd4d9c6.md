# 三层架构迁移：基座仓 nuwa-electron-shell + nuwaclaw/nuwa-work 双产品壳

（命名定稿：**nuwa-electron-shell**，全名 `nuwax-ai/nuwa-electron-shell`——自描述"Electron 外壳基座"，与 nuwa-work/nuwa-cli 同前缀族；如后续想改名，`gh repo rename` 一步即可且旧 URL 自动重定向。）

## 目标拓扑

```
nuwa-electron-shell（基座仓，公开，复用今天已建的 nucaclaw-work 改名）
└── main = 全部功能模块（~11 万行 TS + agent-kit + gui-server + sandbox-helper
    + nuwax 子模块 + Makefile + 1585 测试）；品牌=4 个 NUWAX_* env，默认即社区版
     ▲ pin                            ▲ pin
nucaclaw 仓（社区产品壳）          nuwa-work 仓（商业产品壳）
= 十几个文件：CI+包壳+默认身份      = 十几个文件：CI+包壳+注入身份
  通道 nuwaclaw-electron             通道 nuwa-work-electron
```

关键结论（来自探索）：品牌已收敛为 `constants.ts`+`autoUpdater.ts` 两处的 4 env 构建期注入，if-commercial 仅 3 处且全读注入常量；`agent-kit` 已验证"独立包+引用"模式；nuwa-work 壳的"submodule + npm pkg set 覆写 + env 注入"构建链今天已实测跑通。**基座无需任何代码改动**，迁移纯属仓库拓扑重组。

## 前提约束（已纳入设计）

- 基座必须**公开**：社区版要真开源，壳引用的代码仓不能私有。
- 不新建任何仓库：基座 = 复用今天已建、历史已推好的 `nuwaclaw-work`（转公开 + 改名 `nuwa-electron-shell`）。
- base 分支模型随之消亡：base 的全部提交都是功能性改进（复刻 UI/IPC 修复等），直接合入基座 main；商业差异只剩壳里的 env 取值。

## Phase 1 — 基座仓定型

1. `nuwax-ai/nucaclaw-work` 转公开（`gh repo edit --visibility public`）并改名 `nuwa-electron-shell`（GitHub 自动重定向旧 URL）。
2. 统一 main：在基座仓内 `merge` 社区 nucaclaw main（19fa6d27）进 base 线 → 分支改名 `base → main`，默认分支 main；archive/electron-client-1.0 保留。
3. 清理 vcpkg 孤儿 gitlink（从 git index 删除该条目，提交）——CI 不再需要为此绕路。
4. 基座 README：定位说明 + 注入契约（4 env 语义 + "不注入=社区版"）+ 双壳引用方式；基座 CI 仅保留 pr.yml 测试（发布都在壳）。
5. 验证：基座仓 clone + `npm run base:test` 基线（1282 用例）通过。

## Phase 2 — nuwa-work 壳切换（流程今天已验证过两次）

1. `.gitmodules` → `github.com/nuwax-ai/nuwa-electron-shell.git`（branch=main）+ `submodule sync` + pin bump。
2. workflow 注释更新（基座公开，github.token 拉取不变）。
3. README 同步流程改写：基座改动 → 壳 pin bump（不再有 merge main→base）。
4. 验证：ci-smoke 探针全绿。

## Phase 3 — nucaclaw 社区仓薄壳化（影响最大的一步）

1. 在 `/Users/workspace/nucaclaw`（独立工作副本）上操作：main 换血为壳结构——镜像 nuwa-work 壳（.gitmodules→基座、package.json base:* 脚本、release-electron.yml 社区身份：不注入 env、通道 nuwaclaw-electron、appId 社区默认），以"delete-files + 新增壳文件"的单提交落盘（保留 git 历史可达性，不用孤儿根）。
2. README/顶部横幅：开发请去 nuwa-electron-shell；本仓=社区产品发布壳。50+ 旧功能分支不动（自然淘汰）。
3. 验证：打一个社区 `prerelease-v*` tag 走通构建（社区版产物名/通道不回归）。
4. 时点由你定（若有社区协作者需提前公告）。

## Phase 4 — 清理与收尾

1. 删 nuwa-work 公开仓上的旧 `base`、`archive/electron-client-1.0` 分支（商业代码公开暴露问题的根治；届时再确认一次）。
2. 外层仓本地 stale 分支（base=85f61f5f 等）清理。
3. 更新记忆（三层拓扑、pin bump 升级流、注入契约）。
4. 最终报告：新拓扑图、日常开发流（基座改功能→两壳 bump）、回滚方式。

## 风险与回滚

- 每个 Phase 独立可回滚（Phase 2/3 = 改回 .gitmodules + pin；Phase 1 分支可恢复），直到 Phase 4 删分支为止。
- 社区仓薄壳化对协作者是破坏性变更 → Phase 3 单独设验证 tag，且执行前和你确认时点。
- 双壳 workflow 靠拷贝维护会有漂移 → 探针 workflow 同时留在两壳做回归。

## 不做的事

- 不把 electron 客户端改成 npm 可发布包（agent-kit 模式）——electron-builder 配置/extraResources 路径参数化工程量大，submodule 引用已够用；留作远期。
- 不动 `DEFAULT_SERVER_HOST` 等后端常量（两产品同后端；分叉时再提为第 5 个注入点）。
